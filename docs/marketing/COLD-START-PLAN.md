# แผน Cold Start — เริ่มทำการตลาดให้ร้านมาสมัคร Quego

> เอกสารนี้เป็น **แผนลำดับการเริ่ม (go-to-market sequencing)** สำหรับช่วงเปิดตัวจริง
> ใช้คู่กับ [`STRATEGY.md`](./STRATEGY.md) ซึ่งเก็บ **ไอเดียการตลาดแบบละเอียด (MKT-01..10)**
> เอกสารนี้ตอบว่า "เริ่มจากอะไรก่อน-หลัง" ส่วน STRATEGY.md ตอบว่า "แต่ละไอเดียทำอะไร"

- **สถานะ ณ วันเขียน:** 2026-06-18 — เพิ่ง deploy production, ข้อมูลใน DB ยังเป็น **mock ทั้งหมด**, **ร้านจริง = 0**
- **โจทย์:** marketplace สองด้าน (ลูกค้า + ร้าน) ที่ยังว่างเปล่า → ต้อง seed ฝั่ง supply (ร้าน) ก่อน
- **north-star metric:** **shop activation** = ร้านที่สมัครแล้ว **เพิ่มบริการจนจองได้จริง** (ไม่ใช่แค่ registered)
- **คอขวดที่รู้แล้ว:** BACKLOG ระบุ 4/5 ร้าน approved ยังจองไม่ได้เพราะไม่เพิ่มบริการ → activation คือจุดที่ต้องโฟกัส ไม่ใช่ยอดสมัครเปล่าๆ

---

## หลักการเดียวที่ต้องจำ

**Supply-first, density-first, by-hand-first.**
อย่าเพิ่งทำ demand marketing (ยิงแอด/SEO หาลูกค้า) ตอนหน้าเว็บยังไม่มีร้านจริง — ลูกค้ามาเจอหน้าเปล่า = เผาเงินทิ้งและทำลาย first impression ให้ seed ร้านด้วยมือในย่านเดียวให้หนาแน่นก่อน แล้วค่อยเปิด demand บน inventory จริง

---

## ขั้นที่ 0 — ล้าง mock data ก่อนทุกอย่าง (บังคับ)

ก่อน launch จริงต้องเคลียร์ข้อมูลปลอมออกจาก production ให้หมด

**ทำไมต้องล้าง:**
- **Trust:** ร้าน/ลูกค้าจริงคนแรกเห็นร้านปลอม/รีวิวปลอม = พังตั้งแต่ first impression และผิดหลัก "ไม่โม้"
- **Metrics integrity (สำคัญกว่า):** ถ้า DB มี mock ปน จะวัด activation จริงไม่ได้เลย — cold start ต้องอ่านตัวเลขจริงออกตั้งแต่วันแรก

**สิ่งที่ต้องลบ:** ร้าน seed ทั้งหมด, bookings / reviews / waitlist ปลอม, customer / staff / service ที่ผูกกับร้าน mock, บัญชี test (admin/ร้าน)

**สิ่งที่ต้องเก็บไว้ (อย่าลบ):** taxonomy ที่ตั้งใจให้มีจริง — `shop_categories`, service presets (เช่น บาร์เบอร์ 8 รายการ), super-admin จริง

**วิธีทำอย่างปลอดภัย (production data — ห้ามลบมั่ว):**
1. Inventory ก่อน — query ดูว่ามีแถวไหนเป็น mock บ้าง (ผ่าน Supabase MCP)
2. โชว์รายการที่จะลบให้เจ้าของยืนยัน
3. ยืนยันแล้วค่อยลบ

**หมายเหตุ:** mock ที่เป็น "ภาพประกอบใน UI" (เช่น `OwnerDashboardMock` ที่โชว์ "12 คิววันนี้ / คุณมานี") เป็นโค้ด ไม่ใช่ข้อมูล DB — ปล่อยไว้ได้ แต่ข้อมูลใน DB ต้องล้าง

## ลำดับการเริ่ม (sequencing)

| ลำดับ | ทำอะไร | เป้าหมาย / ทำไม |
|---|---|---|
| **0** | ล้าง mock data + ทำ **1 ร้านอ้างอิง** ให้สมบูรณ์แบบ (บริการ/ราคา/รูป/เวลาครบ จองได้จริง) | ใช้เป็น demo + proof ตัวแรกตอนไปชวนร้านอื่น |
| **1** | **Concierge seeding** — ลงมือชวน **10–20 ร้านใน "ย่านเดียว"** และ **ช่วยตั้งค่าให้เสร็จถึงขั้นจองได้** (ไม่ใช่แค่ให้สมัครแล้วปล่อย) | density ในย่านเดียว > กระจายทั่วเมือง; ปิดคอขวด activation ด้วยมือ → ดู [MKT-06] |
| **2** | เปิด **on-premise QR** ให้ร้านที่ activate — ดึงลูกค้าเดิมของร้านเข้ามาจองครั้งหน้า (`/shop/share` มีอยู่แล้ว) | ร้านเห็นค่าเร็ว = ไม่เลิกใช้; ได้ booking จริงตัวแรก → ดู [MKT-08] |
| **3** | พอมี ~20 ร้าน + booking จริงแล้ว ค่อยเปิด **demand** (SEO / LINE / referral) บน inventory จริง | ตอนนี้หน้าเว็บมีของให้จองแล้ว ยิง demand ถึงคุ้ม |

**จุดเริ่มที่ถูกต้องตอนนี้ = ขั้น 0 + 1** ไม่ใช่แคมเปญออนไลน์
เลือกย่านที่เข้าถึงร้านได้ง่ายสุด (ใกล้ตัว / มี connection) แล้วลุยทีละร้าน

## กลยุทธ์ราคา — เปลี่ยน "ฟรีถึงสิ้นปี" เป็น "Founding Shops"

ไอเดียเปิดให้ใช้ฟรีดี แต่คำว่า **"ฟรีถึงสิ้นปี" มีกับดัก** — มันสื่อว่า "ปีหน้าจะเก็บเงิน" ซึ่งตอน cold start ที่ต้องการ zero friction มันสร้าง **ความลังเล** มากกว่าความเร่งด่วน

**ปรับ framing:**
- ❌ "ใช้ฟรีถึง 31 ธ.ค. 2026"
- ✅ **"ร้าน 100 ร้านแรก = ร้านผู้ก่อตั้ง (Founding Shops) ใช้ฟรีถาวร + ล็อกสิทธิ์พิเศษตลอดไป"**

**ทำไมดีกว่า:**
- **urgency จากของจำกัด** (100 ร้านแรก) แทน urgency จาก deadline ที่น่ากลัว
- **ไม่มีความกลัว "เดี๋ยวโดนเก็บเงิน"** → ลด objection "ของฟรีหลอก เดี๋ยวเก็บทีหลัง"
- เปลี่ยนคนสมัครให้รู้สึกเป็น **insider / หุ้นส่วน** ไม่ใช่หนูทดลอง

**ใช้ "สิ้นปี 2026" เป็น milestone ภายใน ไม่ใช่ขู่ลูกค้า:**
สิ้นปีคือเส้นตายที่ **เรา** ต้องตัดสินใจ pricing โดยใช้ของที่เก็บได้ในช่วงฟรี —
- proof: testimonial / case study จากร้านจริง (ของที่หน้าแรกยังขาด)
- ตัวเลข activation / booking จริง → ตั้งราคาบนข้อมูล ไม่ใช่เดา
- **price anchor ~฿500/เดือน** (ไม่ใช่ ฿1,500) — benchmark จริง FoxConnect Solo effective ~฿500/mo, ~฿5,000/ปี (ดู STRATEGY.md §4)

**Non-goals ด้านราคา:** ไม่เก็บเงินร้านเร็วจนกว่าจะถึง liquidity (ไม่งั้นพังจุดขาย "ฟรี") · ไม่ทำแคมเปญส่วนลด/cashback (฿0 monetization สู้ GoWabi ไม่ได้)
