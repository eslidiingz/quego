## 1. TL;DR / แนวทาง

**สี่ข้อค้นพบที่เปลี่ยนกลยุทธ์รอบนี้:**

1. **เราโฆษณาฟีเจอร์ที่ไม่มีอยู่จริง** [FACT] — หน้า landing อ้าง "แจ้งเตือนอัตโนมัติ / เตือนเมื่อใกล้ถึงคิว" อย่างน้อย **7 จุด** รวมทั้งใน FAQ แต่ **ไม่มี implementation เลย** ไม่มี cron ไม่มี scheduler ไม่มี `vercel.json`; LINE push ที่มีเป็น event-driven ล้วน **ไม่มีการเตือนก่อนถึงคิวแม้แต่ตัวเดียว** ในตลาดที่ objection อันดับ 1 คือ "ของฟรี = หลอก" นี่คือความเสี่ยงที่ใหญ่กว่าคู่แข่งทุกราย
2. **Loyalty / stamp-card / referral ถูกลบทั้งหมด** เมื่อ 2026-07-01 (commit `19bdade`) [FACT] → **เสาที่ 3 ของ wedge 4 เสาหายไป** และ STRATEGY.md ที่อ้างว่า retention compound ผ่าน "CRM/loyalty/referral" ตอนนี้ผิด 2 ใน 3 ส่วน
3. **LINE เริ่มลงมาเล่นเองแล้ว** [FACT] — LINE ไทยเปิด **LINE MINI Eats** เมื่อ **2026-05-05** ราคา ฿1,700/เดือน (โปร ฿1,390 ถึง 2026-09-30) เป็น mini app แรกที่ LINE ทำเองเพื่อ **แทนที่การต่อคิวหน้าร้าน** ของร้านอาหาร ยังไม่มีเวอร์ชันความงาม **แต่พิสูจน์แล้วว่า LINE ยอมสร้างและเก็บเงินจาก vertical app ที่แก้ปัญหาเดียวกับเรา** และเอเจนซีไทยก็ใช้ LINE MINI App สร้างระบบจองให้สปา/นวด/ร้านเสริมสวยอยู่แล้ว
4. **"ฟรี" ไม่ใช่ wedge อีกต่อไป** [FACT] — **BookQ** ประกาศ "ใช้ฟรีตลอดไป" สำหรับร้านเล็บ, **GoWabi** ไม่เก็บค่าธรรมเนียมรายเดือนเลย (คิดคอมมิชชันเมื่อมีการจองจริง) และมี partner 8,000+ ร้าน, **ZERVA** ทดลองฟรีไม่จำกัด → ตลาด micro-SaaS จอง-คิวไทยแออัดและราคาลงไปถึง ฿0 แล้ว

**ข่าวดีที่แก้ความเข้าใจผิดจาก baseline** [FACT]: push ทั้งหมดออกจาก LINE OA **ตัวเดียวของ Quego** (`src/lib/line/config.ts:25`) → โควต้าที่ถูกเผา **เป็นของเรา ไม่ใช่ของร้าน** baseline กลัวว่าจะไปเผาโควต้าร้านแล้วทำให้ "ฟรี" พัง — **ไม่จริง** และการที่เรารับต้นทุน LINE เองคือ **จุดขายที่ควรพูดตรง ๆ**: ร้านไม่ต้องอัปแพ็กเกจ LINE OA

**ทิศทางที่แนะนำ:** wedge เหลือของจริง **2 เสา** คือ **engine ลึกต่อช่าง (GiST)** กับ **live queue ต่อเลนช่าง** — และเสาที่ 2 ยัง**ทำงานไม่ครบวงเพราะไม่มี reminder** ดังนั้น 90 วันนี้ **หยุดเพิ่มฟีเจอร์ใหม่ แล้วทำให้สิ่งที่ขายไปแล้วเป็นจริง**

## 7. ส่วนที่ 5 — Strategic call

**1. wedge 4 เสา เหลือกี่เสา — ขึ้นกับว่ามองด้วยเลนส์ไหน (ข้อถกเถียงกับ @marketing-manager)**

loyalty ถูกลบ [FACT] · "ฟรี" ในฐานะ **ราคา** กลายเป็นราคาตลาด (BookQ ฟรีตลอดไป, GoWabi ฿0 คงที่, ZERVA ทดลองฟรีไม่จำกัด) [FACT]

**@marketing-manager แย้งว่าผมประเมินต่ำไป และผมยอมรับ 1 ข้อ ครึ่งข้อ:**

- ✅ **ยอมรับเต็ม — "live queue แบบ pull" เป็นเสาจริงวันนี้** เขาเสนอ framing *"ลูกค้ารู้เองว่าเหลืออีกกี่คิว"* (เปิดดูเอง ผ่าน `LiveBookingQueue` polling ฝั่ง client) ซึ่ง **ถูกต้องและดีกว่าที่ผมเขียน** — เป็นคำสัญญาเรื่องคิวข้อเดียวที่เรารักษาได้จริงโดยไม่ต้องมี scheduler **แต่มีเงื่อนไข:** supporting copy ปัจจุบันสัญญาเกินกว่า pull ไปแล้ว (`ValueProps.tsx:27` และ `HomeFAQ.tsx:23` เขียนว่า **"ไม่พลาดแม้ออกไปทำธุระข้างนอก"** ซึ่งเป็น push promise โดยนิยาม) → **ใช้ framing pull ได้ แต่ต้องแก้ supporting copy พร้อมกัน ไม่ใช่แค่เปลี่ยน headline**

- ⚠️ **ยอมรับครึ่งเดียว — "ร้านไม่ต้องจ่ายค่า LINE" ยังไม่ใช่เสาเต็ม** เขาถูกที่ว่าคู่แข่งที่วิ่งบน OA ของร้าน **พูดตามไม่ได้เชิงโครงสร้าง** แต่มี **ผลข้างเคียงที่ยังไม่มีใครนับ**: เพราะข้อความออกจาก OA ของ Quego **ลูกค้าไม่ได้กลายเป็นเพื่อนใน OA ของร้าน** → ร้านไม่ได้สะสม **สินทรัพย์การตลาดที่เป็นของตัวเอง** ในขณะที่ร้านที่ใช้ BeTask/FoxConnect ได้ friend list ที่ broadcast โปรได้ตลอดไปแม้เลิกใช้ vendor
  - สำหรับร้าน**ที่ยังไม่มี OA** → เป็นข้อได้เปรียบจริง (ต้นทุน ฿0 ตั้งค่า ฿0)
  - สำหรับร้าน**ที่ลงทุนกับ OA แล้ว** → เป็น **จุดอ่อนที่คู่แข่งโจมตีได้ตรง ๆ**: *"ลูกค้าไม่ได้เป็นเพื่อนกับ OA ร้านคุณ คุณ broadcast เองไม่ได้"*
  - และมันเป็น **cost-structure choice ไม่ใช่ moat ที่ทบต้น** — ไม่แข็งขึ้นตามการใช้งาน แถม COGS โตเชิงเส้นตามจำนวนการจองขณะที่รายได้ ฿0
  - → **[REC] จัดเป็น "ข้อได้เปรียบเชิง segment" ไม่ใช่เสาสากล** และใช้เป็นหัวหอกเฉพาะกับร้านที่ยังไม่มี OA

**ข้อสรุปร่วม:** ในเชิง **messaging** เขาถูก — วันนี้ขายได้จริง 2 อย่าง (total-cost + live-queue-pull) · ในเชิง **defensibility** ผมยังยืนว่าบางกว่านั้น เพราะ 1 ใน 2 นั้นไม่ทบต้นและมีจุดอ่อนซ่อนอยู่ **สองมุมนี้ไม่ขัดกัน — คนละเลนส์** และทั้งคู่นำไปสู่ข้อสรุปเดียวกัน: **A1 (reminder) เปลี่ยนสถานะจาก "เพิ่มคุณค่า" เป็น "ปิดหนี้คำสัญญาที่ประกาศไปแล้ว" → ต้องขึ้นก่อนงานอื่น**

**2. moat ถูกกัดเซาะจาก 3 ทิศ ไม่ใช่ 1**
บน: LINE ลงมาทำ vertical mini app เองแล้ว (MINI Eats, พ.ค. 2026) [FACT] · ข้าง: ตลาด micro-SaaS จองไทยแออัดและฟรี [FACT] · ล่าง: GoWabi ยึด discovery ด้วยโครงสร้างราคา ฿0 คงที่ [FACT]
**แต่ข่าวดี:** ไม่มีคู่แข่งรายใดที่ยืนยันได้ว่ามี **live queue ต่อเลนช่าง + GiST race-safety** — QueQ มีคิวสดแต่ **จองจากบ้านไม่ได้ (proximity-gated)** [FACT] ซึ่งเป็นจุดตายที่ตรงข้ามกับพฤติกรรมลูกค้าความงามพอดี

**3. ความเสี่ยงสูงสุดไม่ใช่คู่แข่ง แต่คือ trust ของเราเอง**
เราโฆษณาฟีเจอร์ที่ไม่มี 7 จุด ในตลาดที่ objection อันดับ 1 คือ "ของฟรี = หลอก" [FACT] ร้านแรก ๆ ที่สมัครแล้วพบว่าไม่มีการเตือนจริง จะเป็น negative word-of-mouth ใน**กลุ่ม LINE ช่าง-เจ้าของร้าน ซึ่งเป็นช่องทาง acquisition หลักของเราเอง** — เสียหายมากกว่าการช้าไป 6 สัปดาห์

**4. ต้นทุน LINE เป็นของเรา = อาวุธ**
฿1,280/เดือนครอบคลุมทั้งระบบถึง ~3,750–7,500 การจอง/เดือน [FACT] **ถูกกว่าที่ร้านเดียวจ่าย BeTask (฿999) หรือ LINE MINI Eats (฿1,700)** → ควรขายตรง ๆ: **"ร้านไม่ต้องอัปแพ็กเกจ LINE OA — เราออกค่าส่งให้"**

**5. ถ้าเลือกได้แค่ข้อเดียวใน 90 วัน — ทำ A1 + A2 คู่กัน: ส่ง reminder loop ให้ครบวง แล้วทำให้ทุกคำบนหน้าเว็บเป็นจริง**
เพราะมันคือสิ่งเดียวที่ (ก) ทำให้ wedge "live-queue concierge" มีตัวตนจริงแทนคำโฆษณา (ข) แก้ JTBD อันดับ 2 ของเจ้าของร้าน (no-show) (ค) **ขายไปแล้ว จึงไม่ต้องพิสูจน์ demand** (ง) ใช้ของที่สร้างไว้แล้วเกือบทั้งหมด ขาดแค่ตัวสั่งตามเวลาตัวเดียว
**ไม่ควรเลือก LIFF เป็นเดิมพันเดียวของ 90 วัน** — effort สูง, ความเสี่ยง LINE first-party ยังไม่ verify, และไม่แก้ปัญหา trust ที่กำลังไหม้อยู่
